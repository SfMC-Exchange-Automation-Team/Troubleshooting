TRUST AND EXTRACT BEFORE RUNNING
  Verify trust and checksum using an approved source/build record.
  Unblock-File the EXACT ZIP BEFORE extraction, then use a fresh unique folder.
  README.md/README.txt provide the checksum and extraction procedure and cite
  Microsoft's Unblock-File documentation:
  https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/unblock-file?view=powershell-5.1

  Unblocking the ZIP after extraction does NOT clear existing file ADS/MOTW.
  Prefer fresh extraction from the verified, unblocked ZIP. For an existing
  kit, first review the WHOLE package including private and verify identities.
  Only then, if policy permits, manually unblock just its scripts/modules/
  manifests. For the exact dedicated kit below, with NO unrelated files:
    $kit = 'C:\Tools\Exchange-KoreanRules'
    Set-Location -LiteralPath $kit
    Get-ChildItem -LiteralPath $kit -Recurse -File |
        Where-Object { $_.Extension -in '.ps1', '.psm1', '.psd1' } |
        Unblock-File
  This includes private, not a broad C:\Temp/shared-tree unblock.
  There is no self-unblock or execution-policy bypass. UAC, publisher trust,
  AllSigned, GPO and WDAC are distinct controls; unblocking is not a guarantee
  that all prompts disappear. Get-ExecutionPolicy -List is a read-only
  diagnostic. Do not disable policies. State-command UAC is unchanged.

OPTIONAL BUNDLED VERIFICATION AND EXPLICIT PREPARATION
  Get does not need payload files. Set does.
  Optional bare Install verifies a complete bundled adjacent payload
  read-only, without prompts, downloads, admin rights, writes or directories:
    .\Install-KoreanRules.ps1

  Only a historical/custom source-only kit with no payload shows help instead,
  without those side effects. Help does not mean payload is ready.
  An invalid or partial adjacent payload fails verification; there is no
  fallback to help, download or another source.

  If fresh media extraction or payload preparation is needed, choose ONE source
  in elevated Windows PowerShell; this is not a public-kit prerequisite:
    .\Install-KoreanRules.ps1 -Download
    # OR an existing EXE, or folder directly containing the EXE/rule BINs:
    .\Install-KoreanRules.ps1 'C:\Temp\SQLEXPR_x64_ENU.exe'
    .\Install-KoreanRules.ps1 'C:\Temp\VerifiedKoreanRules'

  First argument is INPUT (SqlPackagePath, alias Path), not a destination.
  Optional second argument is a NEW output directory:
    .\Install-KoreanRules.ps1 '.\Media\SQLEXPR_x64_ENU.exe' 'C:\Temp\PreparedRules'
  To request portable output while downloading:
    .\Install-KoreanRules.ps1 -Download -OutputDirectory 'C:\Temp\PreparedDownload'
  With bundled payload, no source/download argument is needed:
    .\Install-KoreanRules.ps1 -OutputDirectory 'C:\Temp\PreparedBundledRules'
  Without bundled payload, this explicit output request fails with an error,
  not silent help or an automatic download. Supply a verified source or
  explicitly choose -Download for portable output from a historical/custom
  source-only kit.
  Only explicit OutputDirectory requests a portable expanded kit PLUS ZIP.
  Existing output folders are refused. Without it, preparation writes only
  adjacent payload: no second kit/ZIP/default KoreanRules-Ready directory and
  no empty work directory for BIN input.

  Folders are not searched recursively. Select the folder directly containing
  SQLEXPR_x64_ENU.exe or ko.token.rule.bin/ko.complex.rule.bin. EXE plus either
  BIN is ambiguous: select the exact EXE or use -RuleSourceDirectory.
  A partial rule pair lists the missing file; no input error autodownloads.
  Quote paths with spaces once. Paired double/single quotes inside a pasted
  path string are accepted; paths/relative paths are literal, never commands.

  Download is an explicit fallback: download approximately 749 MB of Microsoft
  media and extract once locally. An existing EXE can also be extracted.
  Install never installs SQL or modifies Exchange. Only media uses unique
  WorkRoot directories (default C:\Temp\KoreanRules-Build) for collision-safe
  extraction/logs. They are retained intentionally, even on success; old user
  directories are never automatically deleted.
  Invalid existing inputs are rejected before work/output creation or execution.
  Media mismatch shows found/required bytes, SHA256 and version. Obtain a fresh
  complete Microsoft copy; smaller files can be incomplete downloads. Do not
  bypass hashes or the required signature, or escalate routine input errors.
  Downloads use SQLEXPR_x64_ENU.partial.exe until identity/signature pass.
  Failures retain available diagnostics, report once and exit 1 by default;
  use -ErrorAction Stop for a catchable automation exception.
  Preparation targets this script folder's payload; portable output is optional.
  Keep the kit writable for preparation; bare verification is read-only.
  Matching exact BINs are reused without rewriting. A missing sibling is added
  only after existing files verify. Mismatch, refused path or write failure is
  a hard error, not overwritten files or hidden fallback. Install never writes
  Exchange Native. The same source folder can be used again.

PREVIEW REMEDIATION
  With verified bundled payload, skip Install. After needed preparation, stay
  in the SAME folder/computer:
    .\Get-KoreanRulesState.ps1
    .\Set-KoreanRulesState.ps1 -WhatIf
    # OR an explicit target:
    .\Set-KoreanRulesState.ps1 EX01 -WhatIf

  An explicit alternate source still takes precedence; failures are not hidden:
    .\Set-KoreanRulesState.ps1 -PayloadDirectory 'C:\Temp\VerifiedKoreanRules' -WhatIf
  No latest-folder scans, guessed paths or persisted global paths are used.

  Set without WhatIf is modifying. Never overwrite existing rules or reapply
  blindly. Restarts require explicit RestartSearch. MaintenanceWindowApproved
  is not required anywhere; it is only a compatibility no-op for old commands.
  Plan an operational window and obtain actual change approval.
  Expected skips: leave unchanged; review actual build, prior receipt or partial
  pair, not routine Support escalation. Partial modifying failures, abandoned
  operations, unstable service/ContentEngine or exceptional rollback still
  warrant Support. Rollback stays Support-approved, local and receipt-bound.
  Restarted remote rollout stays serial and requires workload checks followed
  by RECOVERED <exact-target-name> for each restarted server.
